# 扩展题库 · RAG 与 Agent（逐题精答）

> 60 题逐题精答。RAG 的问题定位三分法与 Agent 的 Infra 化答法是两个差异化亮点。

## A. RAG 基础与流程

**A1. 什么是 RAG？与传统「先检索再生成」的本质差异？**
检索增强生成：生成前先从外部知识库检索相关片段拼入上下文。本质差异不是「多了一步检索」，而是**把参数化知识换成非参数化知识**——知识可更新（不重训）、可溯源（引用定位）、可审计（删库即撤权）。标准不足：检索噪声污染上下文、多跳问题检索不完整、知识库质量决定上限。

**A2. 完整流程与优化策略？**
离线：文档解析 → 切分（固定长度/语义/父子块）→ embedding → 索引（HNSW/IVF-PQ）。在线：查询改写 → 检索（稠密 + BM25 混合）→ 重排（cross-encoder）→ 上下文拼装（按证据排序、去重）→ 生成（引用约束）。优化各环节：HyDE（假设文档增强检索）、multi-query、rerank、上下文压缩、自反思（Self-RAG 判断要不要检索）。

**A3. 检索模块实现方案？（×2）**
向量库（FAISS/Milvus/pgvector——稠密语义）、倒排/BM25（精确词面）、混合检索 RRF 融合、知识图谱（结构化关系）、SQL（结构化数据）。选型：语义模糊→向量；术语精确/编号→BM25；多跳→Graph RAG。

**A4. 向量检索方法与技术选型？**
暴力检索（精确，<10 万条可用）、HNSW（图索引，高召回低延迟，内存大）、IVF-PQ（聚类+量化，内存小精度折损）。三角：召回率-延迟-内存。百万级起步 HNSW；亿级+成本敏感 IVF-PQ。

**A5. TF-IDF 验证的作用？**
在语义检索之外提供词面信号校验：embedding 召回的「语义相似」可能术语不对（型号/法条编号必须精确匹配），TF-IDF/BM25 结果与向量结果交叉验证可发现这类错配——这也是混合检索的动机。

## B. RAG 排障与评估（面试官最爱）

**B1. 如何判断问题出在检索还是生成？**
三分法：**检索不到**（recall 问题——改 embedding 模型/切分策略/索引参数）、**检索到但排不对**（ranking 问题——加 rerank/查询改写）、**检索对了答错**（生成问题——上下文冲突处理/提示词/模型能力）。用中间指标定位：检索层 recall@k 与 MRR，生成层忠实度。

**B2. 召回结果语义相似但事实无关，怎么优化？**
embedding 空间的「语义相似 ≠ 事实相关」（问「A 的创始人」，召回所有讲 A 的段落）。优化：混合检索补 BM25 精确信号、rerank 用 cross-encoder 重新判相关、查询改写聚焦实体、元数据过滤（时间/来源/类别先筛后检索）。

**B3. 用户问题在知识库存在但未召回，怎么排查？**
链式排查：① 切分是否把答案切断（调整 chunk/overlap/父子块）；② embedding 对专业术语不敏感（换领域微调过的 embedding 或加同义词扩展）；③ 查询与文档表述差异大（查询改写/HyDE）；④ 索引参数（HNSW ef_search 调大）；⑤ top-k 太小。

**B4. 检索到了正确文档但答案有误，怎么定位？**
生成侧：上下文里有多文档冲突（需来源权重/时间戳）、上下文太长模型忽略中段（lost in the middle——重排把关键证据放头尾）、提示词未强制引用、模型能力上限。验证：单独喂该文档让模型回答（隔离测试）——答对则问题在拼装，答错则是模型/提示。

**B5. 跨多文档的问题怎么处理？**
多跳检索：先检第一跳 → 用结果改写查询再检第二跳（迭代式）；或查询分解（把复合问题拆成子问题分别检索再汇总）；Graph RAG 预建实体关系索引支持链式遍历。

**B6. RAG 评估体系？（×3）**
检索层：recall@k、MRR、nDCG。生成层：忠实度 faithfulness（答案是否被检索内容支撑——RAGAS 用 LLM 抽取答案声明再逐条验证）、答案相关性、上下文精确率/召回率。框架：RAGAS、TruLens。端到端：人工抽检 + LLM-as-Judge（注意位置/长度偏差）。

**B7. 知识库数据清洗与构造？质量不一致的影响？**
去重（完全/近似）、格式归一（PDF/表格解析纠错）、元数据补全（时间/来源/权限）、敏感信息处理。质量影响是放大的：垃圾文档被检索到会直接污染上下文（比检索不到更糟——模型会一本正经地引用它）；低质量库的 RAG 上限低于不用 RAG。

**B8. 面向 RAG 的生成模型怎么训练？**
检索感知训练：输入含正例与负例检索片段，教模型忽略不相关内容（噪抗）；引用生成训练（每个句子标注来源）；上下文冲突消解数据。进阶：Self-RAG 的反思 token（要不要检索/检索质量够不够）。

**B9. 生成式搜索/排序能否保证 top-1 准确？如何提升？**
不能保证——生成式检索（用 LM 直接生成 docid）有幻觉风险。提升：约束解码（只生成合法 docid）、beam 多候选交叉验证、与传统检索结果融合（生成式做召回补充而非替代）、落地时 top-1 兜底回退到精确检索。

**B10. RAG 封装为 Agent 形态的好处？**
从「被动检索」升级为「主动策略」：Agent 可以决定要不要检索、检索什么、迭代几轮、何时停止；可组合工具（向量库+SQL+API）；可加验证环节（检索后自检）。代价：延迟与不确定性上升——简单 QA 场景纯 RAG 更稳。

## C. Agent 系统（2026 上升最快）

**C1. Agent 应用需要哪些核心模块？（×3 架构题）**
五件套：**规划**（任务分解 ReAct/Plan-and-Execute、反思重试）、**记忆**（短期对话窗口 + 长期向量库/结构化摘要）、**工具**（schema 声明、调用调度、失败重试与降级）、**上下文管理**（Token 预算分配、历史压缩）、**护栏**（输出校验、权限、循环上限）。

**C2. 多 Agent 系统怎么分工？输入输出？**
按职责切：规划 Agent（拆解任务，输入目标输出子任务 DAG）、执行 Agent（各带领域工具，输入子任务输出结果+日志）、汇总 Agent（合并与冲突消解）。协作模式：pipeline（串行传递）、黑板（共享状态）、辩论（多 Agent 互评）。

**C3. 记忆模块怎么设计？管理策略？**
三层：工作记忆（当前对话窗口）、情景记忆（会话历史，按 session 检索）、语义记忆（沉淀的知识，向量库）。管理策略：写入判重（embedding 相似度阈值）、衰减（时间权重）、反思压缩（定期把对话摘要成事实写入长期库）、容量驱逐（LRU + 重要性分）。

**C4. 对话记录用什么数据结构保存？**
短期：消息列表（role/content/token 数）；检索需求：向量库（session_id + embedding + 元数据）；结构化需求：图数据库（实体关系）或 KV（session → summary）。工程上常见三层：热 session 内存 → 完整记录 DB（时序）→ 检索层向量库。

**C5. 评估体系？规划质量与幻觉频率怎么度量？**
任务级：完成率、步骤效率（实际步数/最优步数）；规划质量：子目标覆盖率、依赖正确性（DAG 无环且顺序合理）、与人类规划的一致率；幻觉频率：事实性抽检——**工具返回值与 Agent 陈述的一致性**（Agent 说「API 返回 X」但实际返回 Y 即幻觉）。

**C6. 工具调用调度怎么设计？异常 Fallback？**
调度：声明式注册（JSON schema）+ 路由（模型选择 or 规则匹配）；依赖关系 DAG 化——无依赖并行、有依赖拓扑序。Fallback 三级：重试（指数退避）→ 降级（备用工具或 LLM 自答）→ 熔断（连续失败标记不可用）；超时独立预算。

**C7. 依次调用 3 个外部工具、高并发下延迟高，怎么优化？（系统设计题）**
先问依赖：无依赖 → `asyncio.gather` 并行；有依赖 → DAG 拓扑 + 提前 prefetch 下一步参数。慢工具三招：**结果缓存**（参数 hash 做 key）、**超时降级**（部分结果 + 标注）、**预热连接池**。Infra 岗加分收尾：Agent 负载 fresh token 仅 19%——把工具结果组织成稳定前缀，prefix cache 与 KV 池化是最大杠杆（多轮 Agent TTFT 可降一个量级）。

**C8. 链路追踪与可观测性？**
每步记录 trace：输入 prompt/工具名与入参出参/耗时/token 数/失败原因；按 session 聚合成轨迹；失败可回放（重注入同输入）。指标：每步延迟分布、工具成功率、token 成本、重试率。落地：OpenTelemetry span 或自建事件流。

**C9. 高可用与鲁棒性怎么保障？**
无状态化（状态外置到存储，实例可随时替换）、工具调用幂等（重试安全）、超时与熔断全覆盖、降级链（Agent→纯 LLM→固定回复）、循环检测与步数上限、会话级隔离（一个 session 崩不传染）。

**C10. Workflow / Agent / Skill 三者区别？**
编排粒度光谱：**Workflow** 固定流程预定义（可控、可测、便宜，适合稳定业务）；**Agent** 自主规划动态决策（灵活、贵、难评估，适合开放任务）；**Skill** 可复用能力包（提示词+工具+流程的封装，是两者的积木）。类比：Workflow 是流水线，Agent 是员工，Skill 是技能手册。

**C11. 主流 Agent 框架及特点？**
LangChain/LangGraph（生态最大，图编排）、LlamaIndex（数据/检索为中心）、AutoGen（多 Agent 对话）、OpenAI Agents SDK（轻量、handoff 机制）、Claude Agent SDK（工具循环+上下文工程）。选型：复杂编排 LangGraph；RAG 中心 LlamaIndex；生产简单回路自研 + SDK 常比框架更可控。

**C12. MCP 开发后怎么评测与迭代？**
工具描述质量（模型选对工具率）、参数生成正确率（schema 校验通过率）、端到端任务完成、延迟与 token 开销。迭代：失败案例聚类改 schema 描述（描述就是模型的 API 文档）、加 few-shot 示例、拆分过大的工具。

**C13. Agentic RL 是什么？**
把 Agent 的多步决策（工具选择/规划）整体作为 RL 训练对象——奖励在任务完成时给出，轨迹级 credit assignment 把回报分到每步；解决 SFT 只能模仿轨迹、无法优化长期结果的问题。难点：长轨迹方差大、奖励稀疏、环境（工具）不稳定。

**C14. Prompt 自动推荐/压缩怎么做？**
推荐：把历史 prompt-效果对建数据集，训练排序模型或直接 LLM 生成候选+评估选优。压缩：LLMLingua 类（小模型算 token 重要性删冗余）、结构化摘要（保留实体/约束丢弃寒暄）、基于 embedding 的聚类去重。目标：token 减半而效果不降。

**C15. Qwen3 快慢思考的实现？**
混合模式：同模型支持 thinking 与 non-thinking 两种生成模式（软开关由 chat template 控制），快思考直出答案、慢思考生成推理链——训练时两种数据混合 + 思考预算控制（超过预算强制收尾）。

**C16. 降低幻觉的常用方法？**
生成侧：RAG 提供事实锚点、约束解码/引用归因（每句标注来源）、自我一致性（多次采样投票）、拒绝回答机制（检索置信度低时明说不知道）；训练侧：RLHF 惩罚编造、RAG 微调让模型忠于上下文；工程侧：温度调低、结构化输出校验。
