# 阅读指南

本知识库回答一个问题：**大模型推理系统中的 KV Cache 应该如何被管理**。它以 LMCache、Mooncake、vLLM 三个系统为主线，覆盖架构、传输、存储、可靠性、安全与选型。

## 这份文档怎么读

**第一次接触 KV Cache 管理**：从第一部分「基础原理」开始，理解 KV Cache 是什么、为什么它吃显存、PagedAttention 如何管理它、Prefix Cache 如何复用它。这四篇是后面所有对比的地基。

**做架构选型**：直接看「总结论」→ 第二部分「总体架构」→「选型建议」。如果时间只够读三篇，读这三篇。

**深入某个子系统**：第二部分按主题独立成篇——传输通路、零拷贝、存储变形、prefix 命中、P2P/PD、Connector 对接、可靠性、控制面。每篇开头有「本篇回答的问题」，可按需跳读。想做跨系统对比（数据搬运 gather vs 地址计算、块保护引用计数 vs 租约、准入控制三种哲学），读第二部分的三篇「机制对比」：H2D/D2H、异步保存与块保护、准入控制与防挤占。想看昇腾生态的内存池化底座（GVA/xcopy/与 Mooncake 路线对照），读「MemFabric Hybrid 深度分析」。想看 SGLang HiCache 与 vLLM-Ascend 的引擎侧池化设计（分层语义/物理缓冲复用/稀疏解码卸载），读「SGLang 与 vLLM-Ascend 池化设计」。想看两个系统内部怎么转（函数级：LMCache 的分配器/锁/优先级线程池/设计模式，Mooncake 的元数据分片/OpLog/CMS/故障体系/EP-PG），读「LMCache 内部机制深潜」与「Mooncake 内部机制深潜」。

**负责安全或多租户**：直接读「威胁模型与安全」和「风险与架构改造建议」。

**评估生产可用性**：读「生产化边界与公开声明审计」——它把两家供应商的公开数字按证据等级拆开，标注哪些可复现、哪些只能作方向参考。

## 证据等级

全文引用的证据分为五级，在涉及争议结论时会显式标注：

| 等级 | 含义 |
|---|---|
| A | 本地源码、官方设计文档可直接验证 |
| B | 官方论文/博客/商业声明，方向可信但不可复现 |
| C | 第三方技术文章，用于概念与视角 |
| D | experimental / work in progress / research prototype |
| E | 缺少可靠公开证据，列为待验证 |

所有分析基于 2026-08-28/29 的本地源码快照（LMCache `a0e4a4c`、Mooncake `0518784`、vLLM `5f213ed`）。这些项目迭代极快，引用行号时请先核对仓库版本。

## 与旧版文档的关系

本知识库由原先 12 份独立文档（主报告 + V2~V12 增量审计）重组而成：部署操作类内容（环境采集命令、验收清单）已按「技术分析为主」的原则精简，核心分析全部保留并重新组织。主要外部参考是 ForceInjection KV Cache 系列（42 篇）与「一研」Mooncake/LMCache 系列微信文章，其重要增量已融入第一部分基础原理各篇。

## 面试备考

第四部分「面试题库」把本知识库的能力收敛为答题：来自 66 家公司 181 场真实面试的 1,646 道去重题按频次排名，推理系统与 CUDA 高频题均有结合本库结论的精答。备考从 [总览与备考策略](/interview/) 开始。
